TL;DR: context always has only short AGENTS.md and skill names; rest loaded via index, TL;DR, and explicit reading; measured with real question set.

## Context
Agents have limited context, and extra text lowers quality and raises cost. Approach "links instead of content": lightweight identifiers always, full content on demand. OpenCode loads skills via `skill` tool: agent sees names and descriptions, body loaded by agent. Files with `instructions` in `opencode.json` are added to `AGENTS.md` **always**, so large documents don't fit there.

## Decision
1. `AGENTS.md` short (rules, map, commands), no doc content.
2. Knowledge needed only sometimes packaged as skills (`.agents/skills/<name>/SKILL.md`, description ≤1024 chars, triggers at top).
3. Every doc has frontmatter and `TL;DR:`; `docs/INDEX.md` generated by script; agents grep index first.
4. Don't add documents to `instructions` in `opencode.json`. For links from `AGENTS.md` use explicit instructions like "read @docs/... only when...".
5. Heavy reading (over ~5 documents) delegated to `explore` and asked for half-pages with references.
6. `compaction.prune: true` so old tool outputs don't eat the window.
7. **Measure:** `docs/evals/retrieval-questions.md`: 10 real questions with known target docs. Monthly check if agent finds them.

## Consequences
Less noise, cheaper sessions. Risk: agent misses what's needed if skill description or TL;DR is weak; so we measure and clean.
